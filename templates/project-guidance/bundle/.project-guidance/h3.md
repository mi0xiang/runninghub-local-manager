# H3管理器补充

仅在[本机上下文](../.project-local/README.md)明确使用RunningHub Local Manager进行H3制作时读取。先定位本机管理器，读其`AGENTS.md`、`START_HERE.md`和`docs/project-runner.md`；这些是实际执行接口的依据。数据根从该安装的`.local/config.json`读取，不沿用另一台电脑的盘符、解释器或数据路径。管理器是技术模块，不当作制作子项目。

当前统一FIFO最多3并发，后续调整需同时核对账户能力、执行器和适用指引。同一账户跨电脑不各自分配3个名额，按[协调职责](roles.md)确认唯一执行队列。

新H3请求每次最长15秒，已核实工作流有更短限制时按更短限制；按实际镜头、完整句意和动作衔接拆段。记录全片与段内时间、初末状态；依赖前段实际结果的后段，等验收和真实稳定帧确认，再核对素材、参数与准确批准。历史冻结方案、批准和task保留原样。

网页手工启动。`watch-results`仅前台、有限接收指定原task，退出停止、重启接续账本；`tick`与旧UI恢复操作可能提交已批准任务，使用前核对范围。全部步骤沿用现有统一接口，不另建队列。

完整交付依次具有真实分段与依赖验收、已冻结后期、整片内容与技术证据、delivery及presentation/子项目页登记和追踪回读。只有合格整片可进入待用户审核，最终确认遵循[共同规则](../AGENTS.md)。这不强制固定创作技能或预览格式。

需要工作流参考输入时读管理器`docs/workflow-rules.md`并核对本次实际导出；需要可选Lark适配时读`docs/supervision-v02.md`。工作流、资源ID、来源单元格及商品资料留本机。模板不附工作流导出、技能安装、素材或历史授权。
