# 职责与文档分工

| 主体 | 负责内容 |
|---|---|
| 总项目 | 共同规则及下游一致性、项目身份与负责人、进度、阻塞、共享资源冲突、遗漏和交付状态 |
| 子项目 | 本项目需求对齐、方法/skill选择、制作方案、获批执行、内容与技术验收、完整交付及接续记录 |
| 管理器/共享脚本 | 按现有接口执行登记、调度、查询、下载、技术检查和已冻结处理；保留真实记录 |
| 用户 | 目标与重要内容选择、需批准的准确批次、最终版本确认；可明确将常规选择交给Codex |

总项目跟踪现有项目记录，具体创作问题由子项目解决。共享状态沿用同一协调路径、锁和修订核对，不覆盖其他活动项目。多台电脑使用同一账户时，确定唯一调度端或已经验证的共同协调机制；各自本机的锁不能协调另一台电脑。代码拉取不迁移任务，也不授权同时调度多个数据副本。

[根入口](../AGENTS.md)维护共同边界；[子项目入口](child.md)维护协作与交付；[复刻咨询](replication.md)只管理复刻需求；[页面边界](pages.md)只管理展示职责；[H3补充](h3.md)只在选用该执行器时生效。实际业务依据和用户项目的技能例外放入[本机上下文](../.project-local/README.md)所指向的私有指引，避免把一个项目的选择套到所有项目。

规则变更从适用入口追到所引用的文件、示例及生成源，更新仍在使用的重复表述；冻结历史保留原样并标明用途。记录规范、当前实现和当前运行状态时分别说明，待实施接口不当作已有能力。
