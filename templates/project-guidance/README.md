# 总项目与子项目指引模板

此目录随Git更新。模板只包含通用规则和可选H3补充；用户资料留在每个项目自己的私有上下文中。因此换电脑后无需另发通用AGENTS，但仍需在当地定位项目、资料和工具。这里不附技能安装、第三方工作流、历史项目或批准。

## 三层内容

| 层次 | 内容 | 更新方式 |
|---|---|---|
| 公共模板 | 总入口、子入口、职责、复刻咨询、音画参考、页面边界、H3补充 | 从Git拉取；检查整个引用链 |
| 私有项目上下文 | 角色、实际资料入口、用户已确认的业务要求、项目/负责人和来源对应 | 项目根`.project-local/README.md`；按项目维护 |
| 本机运行配置及数据 | 工具路径、数据根、资源标识、任务、素材、批准与结果 | 管理器`.local/config.json`及仓库外数据根；不随Git更新 |

不要把现有业务AGENTS或制作文件原样复制回模板。只提取确实通用的规则；来源链接、商品知识、历史样例、单元格/账号标识和个人目录留在私有层。凭据不写入上下文。

## 新项目安装

在管理器仓库中运行以下命令，输入**管理器代码目录之外**的项目根目录；中文、空格和不同盘符均可。

```powershell
$projectRoot = Read-Host '本机项目根目录'
python scripts/project_guidance.py --project "$projectRoot"
# 预览无冲突后执行；不上传、不调用生成、不改管理器配置
python scripts/project_guidance.py --project "$projectRoot" --apply
```

需要Python 3.12+。默认仅预览；`--apply`安装固定清单中的8份公共文件，初始化私有上下文和模板哈希记录，并在目标`.gitignore`追加`/.project-local/`。不读取或搬运现有生产数据。发生冲突时退出码为2，本次不写入文件。

| 安装后的入口 | 用途 |
|---|---|
| `AGENTS.md` | 总项目基本规则与按工作读取的入口 |
| `.project-guidance/child.md` | 子项目的自主制作与交付职责 |
| `.project-guidance/roles.md` | 责任分工、跨机协调和文档归属 |
| `.project-guidance/replication.md` | 每条新复刻的需求咨询 |
| `.project-guidance/audio-visual.md` | 按需音画核对，方法自由选择 |
| `.project-guidance/pages.md` | 总页、子页及历史页面的边界 |
| `.project-guidance/h3.md` | 仅采用H3管理器时适用的执行规则 |
| `.project-guidance/tshirt-replication.md` | 仅T恤业务适用的复刻提示，不含商品事实 |
| `.project-local/README.md` | 当前电脑和项目的私有绑定；参考[空白示例](local-context.example.md) |

让Codex结合本机现有目录、配置和用户要求补齐私有上下文。字段是定位提示，不必一次问完；缺失信息只在相关操作需要时确认。通用规则不固定商品、语言或skill；可选T恤补充保留已确认的复刻技能适用边界，不套到其他业务。本项目的特殊选择写入私有业务指引并提供读取入口。

旧业务文档的拆分对应：`Lark竞品T恤视频到本机H3制作`的通用部分进入复刻咨询、T恤补充及H3补充；`复刻视频与口播匹配指引`的通用部分进入音画参考；原有页面规范只提取页面职责。真实来源、商品知识、33稿内容、样衣目录、历史项目与工作流归属仍在私有层，不随模板发布。

总目录下的制作子聊天通过根AGENTS主动读子入口；单独工作区的子项目可在自己的根目录安装同一套入口，在私有上下文标明子项目角色和共享协调方。不要把管理器自身的AGENTS当成制作指引，也不要依赖另一个目录的规则自动加载。

## 已有项目与后续更新

`git pull --ff-only`只更新管理器中的模板源，不直接覆盖已安装指引。再次运行上述预览命令，核对输出；未修改的模板可用`--apply`更新，私有上下文保持原字节。安装器不启动项目或服务。

已有AGENTS、定制过或主动删除过的模板文件会报告`conflict`。让Codex把新模板与当前文件逐项比对，保留已有有效业务要求，把私有内容留在私有层，并核对所有下游链接与生成源。不要用强制覆盖、删哈希或修改哈希记录来跳过差异。这个小工具不做自动三方合并；保留定制的文件以后继续按差异人工合并即可。状态文件损坏时先保留，再核对已有内容。

只有项目专属内容时，优先写入私有业务指引，减少公共模板的定制。已在使用的老项目无需为了换模板迁移文件或重建台账；可以保留原入口并对照模板整合。

忽略规则不能撤回已经被Git跟踪或已上传的内容。接入已有Git项目时检查其跟踪清单；确认私有目录未被跟踪，再提交公共内容。发布前按[公共仓库说明](../../docs/publishing.md)检查实际暂存内容及发布包。

## 换电脑接手

1. 更新或克隆管理器仓库，读[START_HERE](../../START_HERE.md)。现有代码修改先处理差异，不强制覆盖。
2. 在本机重新确定项目位置、数据根和工具路径。运行配置按[安装说明](../../README.md)初始化/检查；不要复用另一台电脑的机器确认。
3. 安装或对照更新本套指引，填写本机私有上下文。继续旧项目需要用户选定的私有资料与原始任务记录；未迁移记录时不要把新空目录当作旧任务的副本并重新生成。
4. 同一账户跨机运行时明确唯一调度端和队列归属。本机锁不是跨机锁；当前3并发是账户共享上限，不能每台电脑各开3个。

可给另一台电脑的Codex这段指令：

> 请先核对本地修改，再从GitHub更新管理器main。阅读templates/project-guidance/README.md，结合当前机器和项目安装或合并总项目、子项目及下游指引。实际路径、来源、商品资料和账号资源信息仅写入本地私有上下文；保留已有任务、批准和项目定制。核对全部引用入口，不自动启动生成、后台任务或Lark写回。
