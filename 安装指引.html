RunningHub Local Manager

0.1.0 后续更新（未发布）· Windows 空白安装 · GitHub 更新程序，本机保存结果

代码与数据分开。此包没有任何历史项目、素材、任务记录、API Key 或个人工作流。不会自动同步到其他电脑，不会在安装时生成视频。

1．准备环境

安装 Windows Python 3.10+。需要下载校验或视频合成时安装 FFmpeg（包含 ffprobe）。将程序解压到任意盘，例如 F:\Apps\runninghub-local-manager；将数据另放在 F:\RunningHubData。

2．填写本机配置

填写项说明
data-dir必须在程序目录之外，支持其他盘
Python初始化自动记住当前解释器
ffmpeg / ffprobe各填完整 exe 路径；已配置 PATH 可直接使用命令名
RUNNINGHUB_API_KEY仅在新电脑的 Windows 用户环境变量中填写；不要放入文件或 GitHub
端口固定127.0.0.1:18765，仅供本机使用

进入程序文件夹打开 PowerShell，运行：

python manage.py init --data-dir 'F:\RunningHubData' --ffmpeg 'F:\ffmpeg\bin\ffmpeg.exe' --ffprobe 'F:\ffmpeg\bin\ffprobe.exe'
python manage.py doctor
python manage.py confirm
python manage.py dashboard

也可右键使用 PowerShell 执行 setup.ps1。检查报告保存到数据目录“环境检查.html”。确认时输入 CONFIRM，不代表批准任何生成任务。

3．打开网页

打开本机项目管理页。初始没有项目；由操作者或 Codex 按 docs/project-format.md 准备素材与工作流，经明确批准后才能进入生成队列。

dashboard 是手动前台只读服务，浏览不查询、上传或提交；Ctrl+C关闭服务。不要在已有中心占用18765端口时同时启动第二套服务。

4．手动收片与 GitHub 更新

按 docs/project-runner.md 准备准确选择清单后，手动运行 watch-results，达到原任务终态、时长或错误预算后停止。python manage.py tick 会推进已批准任务，可能上传和生成。原有 web、start.ps1 默认 Web 模式及 InstallQueueTask 仍保留；web 会渲染历史页并周期收片，计划任务会周期提交获批工作。它们需要相应授权，当前手动制作流程不启用系统任务。

更新代码前停止网页和队列、备份本机数据，运行 git pull --ff-only，再运行测试和环境检查。不需要将视频、项目或配置提交到 GitHub。当前不提供无人值守自动更新。

给新对话的接手指令

请阅读本程序目录中的 AGENTS.md、START_HERE.md 和 README.md。
从 .local/config.json 定位本机数据目录，读取 projects.json 选择项目。
先核对批准记录、原 taskId 与现有成片，不重提已有任务。
代码通过 GitHub 更新；项目、素材、日志和结果保持本机保存。

规则与边界

  • 新增、改稿及失败重跑必须明确批准；状态不明不能自动重提。
  • 素材开关按实际图像/音频/视频数量匹配；不擅自修改采样、模型和放大。
  • 第三方工作流需自行提供。本包不分发模型或工作流原件。
  • 本版已做离线安装与核心回归测试；独立版的真实云端生成仍需使用者按任务验收。

详细说明见 README.md、docs/workflow-rules.md、docs/project-format.md 和 docs/publishing.md。
