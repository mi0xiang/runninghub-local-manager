# 工作流与参考规则

以下映射仅针对 RunningHub 工作流 `2097955216049131522` 的已核实原生API导出版本。平台工作流可能更新；每次准备时对照实际导出和哈希验证，不能假定任意版本都相同。用户应自行获取可用工作流；公共包不提供模型或第三方导出原件。

|类型|按顺序的节点ID|节点类型/字段|265入口|
|---|---|---|---|
|图片1–8|51,49,50,43,19,23,199,200|LoadImage.image|ref_images.ref_image_0…7|
|音频1–3|48,14,15|LoadAudio.audio|ref_audios.ref_audio_0…2|
|视频1–3|27,25,26|VHS_LoadVideo.video|ref_videos.ref_video_0…2|

三类各自按实际素材数量启用前N路。数量、素材路径、节点ID和提示词标签必须一一对应。无该类参考则全部关闭且不上传，不能传空字符串、None或旧文件名。上传返回fileName绑定原生字段，并同步nodeInfoList；保存上传映射。

307/308/309是前端分组开关，API导出inputs为空，不存在可凭空填写的布尔字段。使用原生导出分支的保留/排除表示开关，同时去除265相应未使用入口；保留内部音频VAE和解码器。两个音频与两个视频使用48/14及27/25，关闭15/26。

native_references.configure处理音视频0–3路，要求完整原生模板；不会配置图片。图片必须另行准备并复核。native_references.verify也不等于完整工作流审计。完成后记录reference_switch_schema=native_20260924。旧模板不静默迁移。

日常修改限定于已授权参考开关/上传绑定、提示词、时长和输出画幅/分辨率。模型、采样器、步数、缩放、二采放大、其他节点连接变化须另外许可。关闭参考不等于关闭模型内部音频处理。

默认创意约定可以采用15秒9:16；公共程序不强改工作流参数。明确批准后才上传/提交，失败重跑需重新批准。第三方模板原件只存本机workflow_baselines并记录SHA-256，不提交到公共仓库。


## API执行图、关闭与上传示例（2026-09-28）

265是MiniMaxH3ReferenceToVideo节点。这里的“开关”指265.inputs实际存在的参考端口及原生加载连接，不是另一个on/off字段。307（图片）、308（音频）、309（视频）界面分组节点在已核实导出中的inputs为空，不向它们提交伪造布尔值。

以3图+2音频+2视频为例，265的参考部分应为以下连接（仅展示参考部分，其他必需输入原样保留）：

```json
{
  "ref_images.ref_image_0": ["51", 0],
  "ref_images.ref_image_1": ["49", 0],
  "ref_images.ref_image_2": ["50", 0],
  "ref_audios.ref_audio_0": ["48", 0],
  "ref_audios.ref_audio_1": ["14", 0],
  "ref_videos.ref_video_0": ["27", 0],
  "ref_videos.ref_video_1": ["25", 0]
}
```

音频3的15、视频3的26及未使用的图片参考分支关闭；265不能遗留相应端口。若不要音频和视频，删除全部ref_audios.*与ref_videos.*参考端口及其专用加载分支；不要删除audio_vae或其他内部音频输入。

获批上传后，每条素材使用自己的返回fileName，例如音频1写入graph["48"]["inputs"]["audio"]，同时对应nodeInfoList条目为：

```json
{"nodeId":"48","fieldName":"audio","fieldValue":"上传接口返回的fileName"}
```

图片字段为image，原生视频字段为video。nodeInfoList用于同步上传绑定，不替代已准备的执行图开关。不能仅省略一次上传而保留旧参考连接。上传清单不包含未启用路，单个返回值不能误配给另一份素材。

顺序：确定素材用途与顺序 → 从已核实原生基准准备分支 → 复核265连接与三类清单 → 保存差异、素材哈希和明确批准 → 逐份上传并绑定 → 再复核执行图及nodeInfoList → 提交并保存taskId。批准后禁止偷偷改参考数量或连接。

关闭分支时先检查其他消费者，只移除该参考专用的未用加载节点；发现共享连接、基准不一致或平台导出改变就停止复核。八图映射来自已核实八图基准，音视频全开导出中仅有两图不能据此直接臆造其余节点。

当前configure/verify辅助函数仅覆盖音视频；图片及文件数、提示词顺序、上传绑定总表需要额外检查。文件数、节点数、启用入口数和绑定数必须逐类相等，且路径/哈希/顺序匹配。文档更新不意味着新增图片自动校验或云端成功验证，不触发任何上传、重跑或模型修改。
